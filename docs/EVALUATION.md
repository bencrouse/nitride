## Low-friction feedback

Play the built-in patches in Logic and tell the assistant what you heard. It can
record that feedback verbatim and separately record an interpretation/proposal.
Example CLI (replace the example text with actual feedback):

```sh
python3 scripts/evaluation.py feedback \
  --trial logic-024 --revision review:classic-voice:r1 \
  --text 'Your actual observations here' \
  --interpretation 'Optional assistant interpretation' \
  --next 'The single next change to evaluate'
```

Decisions use `decision --revision ID --status STATUS --reason TEXT`. Statuses:
`awaiting-trial`, `in-trial`, `needs-revision`, `direction-kept`, `parked`,
`approved`. Library approval must be explicitly authored by the user. The initial
"these patches are good" reaction is not final category/library approval.

Use `--supersedes EVENT_ID` for corrected feedback/decisions. Original entries
remain in the journal. There is no automatic parameter/MIDI/audio telemetry and
no filesystem logging in the audio callback.

## Integrity and backup

```sh
make evaluation-verify
python3 scripts/evaluation.py rebuild
make evaluation-backup BACKUP="$PWD/evaluation-snapshots/eval-024.zip"
```

Journal writes use a single-writer file lock and flushed append. Derived files
use atomic replacement. Checksum/sequence failures stop processing rather than
silently accepting edited history. If a crash leaves an incomplete final record,
`recover-tail` explicitly saves the entire original journal under diagnostics,
then replays complete records. Complete-record corruption requires inspection.

Backup refuses an existing output or an output inside `evaluation/`. It includes
the journal, frozen revisions, trial context, reports, audio and recorded build
archives. A ZIP beside the checkout protects against build cleanup, **not disk
loss**; copy it to your backup storage. No automatic cloud sync is enabled.

Local tests cover projection rebuilding, verbatim/corrected feedback, corruption,
torn-tail recovery, frozen evidence, backup guards and approval restrictions.
The synth's existing F1 headroom limits remain open; journal or offline success
does not establish Logic listening results or universal real-time qualification.
